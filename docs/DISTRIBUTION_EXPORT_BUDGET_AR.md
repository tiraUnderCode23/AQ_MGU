# ميزانية تصدير التوزيعات وحدود النقل

تُراجع ميزانية كل توزيع في `distributions.<name>.export_budget_bytes` داخل
[دليل الاختيار](../data/id8-eligibility-20261120.json). القيمة الافتراضية تبقى
`209715200` بايت، أي **200 MiB**. المراجعة المؤرخة في 2026-11-20 اعتمدت
**256 MiB لـ ID8** و**200 MiB للألعاب**، مع سقف ثابت **512 MiB** لأي توزيع.
كل MiB يساوي 1,048,576 بايت. لا تتغير حدود حزم Manager أو إعدادات المتجر بهذا القرار.

```json
{
  "distributions": {
    "id8": {"export_budget_bytes": 268435456},
    "games": {"export_budget_bytes": 209715200}
  }
}
```

هذا مقتطف لحقول الميزانية فقط؛ تبقى بقية بيانات الهوية والاختيار والتبعيات مطلوبة.
ترفض الأداة القيم المنطقية والنصية والعشرية، والصفر والسالب، وأي قيمة تتجاوز السقف.
زيادة ميزانية توزيع واحد لا تغيّر افتراضات التوزيعات الأخرى.

## أساس القرار

قيس الاختيار المثبت عند commit
`2a0e23fded8aecf0b7345754ceae4da6992821b1` من كائنات Git فقط، دون إنشاء تصدير
أو تنزيل أو تشغيل بناء. بصمة دليل الاختيار المستخدم:
`68e149089e19e2da1004adb75bef0b64f672fd5540add56a884cebeead43ccc6`.

| الحجم المحسوب بالبايت | ID8، 74 اختيارًا | الألعاب، 40 اختيارًا |
| --- | ---: | ---: |
| ملفات المصدر المحفوظة، بما فيها الوسائط والتوثيق | 226,266,502 | 91,693,078 |
| الملفات المولدة | 2,746,810 | 2,610,453 |
| خطة التصدير JSON | 4,170,244 | 3,457,629 |
| إيصال الإكمال JSON | 483,202 | 400,598 |
| المجموع الشامل | **233,666,758** | **98,161,758** |
| المجموع بـ MiB | **222.842** | **93.614** |

هذه قياسات مرجعية قبل إضافة حقول الميزانية والمحاسبة الجديدة؛ تُحسب أرقام النسخة
المثبتة النهائية من جديد عند التخطيط. الحجم يشمل الملفات الأصلية المتكررة في مسارات
مختلفة، ومنها بيانات الترجمة، وكذلك الصور المحلية المطلوبة. لم تُحذف هذه المدخلات
ولم تُبدّل مراجعها لتلائم ميزانية أصغر. حمولات الإصدارات الخارجية التي يصفها الكتالوج
تبقى مراجع إلى ناشرها، ولا تدخل في الحجم بوصفها ملفات منزلة.

## ما الذي تحسبه الأداة؟

[أداة التخطيط](../tools/plan_distribution_branches.py) تحسب بايتات كل ملف محتوى،
وكل ملف مولد، و`.distribution/plan.json` و`.distribution/receipt.json`، وتعدّ الملفين
الأخيرين ضمن حد **20,000 ملف**. لا يمثل الرقم مساحة قرص محجوزة أو حجم ضغط ZIP/TGZ.

تسجل الخطة والإيصال المجموع في `totals` والميزانية الفعلية في `limits.bytes` والسقف
الثابت في `limits.hard_bytes`. تُحسب أطوال JSON الدقيقة عبر تقارب محدود بـ 16 خطوة؛
تتغير أطوال العدادات العشرية فقط، بينما طول SHA-256 ثابت. عدم التقارب أو تجاوز الميزانية
يوقف العملية. قبل إنشاء مجلد الإخراج تعاد مطابقة الميزانية بدليل الاختيار، ويعاد فحص
مجموع الخطة والإيصال. يسجل الإيصال بصمات بقية الملفات؛ يدخل حجمه هو أيضًا في المجموع
دون ادعاء بصمة ذاتية دائرية.

## الفرع الكامل وملفات التطبيق المختار

في [المتجر الأصلي، sources.js](../tools/_sources/mgu-store/native/mgu-updater/js/sources.js)،
تحدد `partPaths` و`contentSpec` مجلد المكوّن ومدخلات `build.shared` والسكربت، أو ملف
الخدمة أو المكتبة المحدد. يقبل المسار الجزئي حتى **400 ملف**، ويتحقق من حجم وهوية Git
لكل ملف. لا يجلب هذا المسار صور التوزيع وتوثيقه وأدلة الاختيار لمجرد وجودها في الفرع.

قياس هذه المسارات عند commit المرجع أعلاه أعطى:

| التوزيع | مكونات المصدر ذات الجلب الجزئي | أكبر عدد ملفات لمكوّن | أكبر حجم لمكوّن |
| --- | ---: | --- | --- |
| ID8 | 50 من 50 | `pps_warmup@1.2.1`: 298 ملفًا، 7,331,128 بايت | `cluster-render@0.6.9`: 8 ملفات، 34,107,354 بايت |
| الألعاب | 15 من 15 | `iabadia_m_arcade@0.1.3`: 126 ملفًا، 1,918,889 بايت | `cluster-render@0.6.9`: 8 ملفات، 34,107,354 بايت |

لم يتجاوز أي اختيار 400 ملف أو 200 MiB، ولم يوجد سكربت مختار يطلب الفرع كاملًا بسبب
غياب `build.shared`، ولم تظهر مسارات مدخلات مفقودة. هذا قياس ساكن لعقد المسارات؛ فحص
الفروع المصدّرة بمحلل المتجر الأصلي يبقى تحققًا منفصلًا.

إذا فشل الجلب الجزئي، يعود المتجر إلى تنزيل الفرع كاملًا. الافتراضات الموجودة في
[updater.js](../tools/_sources/mgu-store/native/mgu-updater/js/updater.js) هي **64 MiB
للتنزيل المضغوط** و**200 MiB للملفات بعد فك الضغط**. لذلك يتجاوز فرع ID8 المرجعي حد
فك الفرع الكامل، حتى مع صلاحية أحجام مجموعات الجلب الجزئي. رفع ميزانية التصدير إلى
256 MiB لا يغيّر هذا السلوك. حجم أرشيف GitHub المضغوط لم يُقس في هذه المراجعة.
أما `WHOLE_BYTES = 96 MiB` في `sources.js` فهو حد احتفاظ بالذاكرة المؤقتة فقط.

هذه المراجعة لا تثبت نجاح بناء أو تثبيت أو تشغيل على وحدة؛ يبقى `runtime` بالقيمة
`NOT_OBSERVED` في الخطة والإيصال.

## التحقق الآلي

تغطي [اختبارات التخطيط](../tests/test_distribution_branch_plan.py) الافتراض 200 MiB،
والميزانية الصريحة 256 MiB، والقيم غير المقبولة والسقف الثابت، واستقلال التوزيعات،
وحساب الخطة والإيصال فعليًا، ورفض مجموع ناقص أو ميزانية تختلف عن الدليل قبل إنشاء
مجلد الإخراج. تستخدم حالة الحجم الكبير أوصاف كائنات اصطناعية، دون تخصيص حمولة ضخمة.

```text
python -X utf8 -B -m unittest discover -s tests -p test_distribution_branch_plan.py
```
